# QA Checklist

## 必过项

- 是 16:9 横版。
- 白底为主，有浅绿色草地色块点缀。
- 有突突（浅米黄单色狗狗）。
- 突突承担核心动作，不只是装饰。
- 没有复刻旧案例构图，而是为当前文章生成了新的童趣隐喻。
- 画面童趣、温暖、简单、干净。
- 简约单线简笔质感，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 主标注用浅绿色，橙色只用于关键提醒或路径箭头。
- 浅蓝色用于次要说明或狗狗配件。
- 不再使用红色。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有"常见坑 / Workflow / 系统架构图 / 路线图"等标题。
- 画面太暗黑、怪诞或荒诞。
- 画面像商业插画、PPT、课程课件、正式流程图。
- 线稿太复杂、密集或阴影过多。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、噪点。
- 突突不是浅米黄单色，或使用了渐变/阴影。
- 突突只是站在旁边当装饰，不参与核心动作。
- 画面颜色压抑（缺少浅绿色/浅米黄的温暖感）。
- 中文错字严重或标注不可读。
- 图上出现颜色代码文字。

## 迭代方法

- 太普通：让突突成为动作主体，加入一个童趣但成立的场景。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 不够童趣：强调 warm、playful、childlike、simple doodle style。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成单线手绘童趣场景。
- 颜色不对：检查是否使用了浅绿色草地块和浅米黄狗狗色，去掉红色。
- 颜色代码上画：检查图上是否有 hex 文字，有则重生成并在 prompt 中明确禁止颜色代码作为标注。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者第一眼感到温暖和童趣，然后在 1-2 秒内看懂画面要表达的故事或结构。

如果第一眼像教程页、商业插画或暗黑怪诞风格，就不合格。
